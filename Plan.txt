## 一、Alpha-Lab 的整体架构

先把你在 6.3 里列的功能简化一下：

* v0：

  * 拉日频数据（股票 / ETF / crypto）
  * 算基础因子：动量 / 价值 / 质量
  * 粗糙回测（不考虑成本）

* v1：

  * train / valid / test 样本外切分
  * 成本 / 滑点模型
  * 指标：年化收益、波动、Sharpe、max drawdown、换手率

* v2：

  * 多因子组合优化（QP + 行业 / 风格约束）
  * Walk-forward 回测
  * Deflated Sharpe 等更严谨检验

* v2.5：

  * 横截面 ML（树 / GBDT / 小网络）
  * 严格样本外评估、防止数据泄露
  * 可视化因子暴露与贡献

* 配套小项目：exec-sim（执行仿真，Almgren-Chriss）

这一堆功能如果你不想搞成一坨脚本，就需要一个干净的模块化结构。建议按「层」来设计。

### 1. 仓库结构（建议）

```text
alpha_lab/
  alpha_lab/
    data/          # 数据获取 & 预处理
    factors/       # 因子计算
    backtest/      # 回测引擎（持仓、成交、PNL）
    portfolio/     # 组合构建 & 优化
    metrics/       # 绩效指标 & 检验
    ml/            # 横截面 ML 模型 & pipeline
    exec_sim/      # 执行仿真（Almgren–Chriss）
    viz/           # 各种图、报表
    config/        # 配置（参数、路径、品种列表）
    utils/         # 公共工具
  notebooks/
    01_factor_demo.ipynb
    02_backtest_demo.ipynb
    03_ml_cross_section.ipynb
  tests/
  README.md
  pyproject.toml / setup.cfg / requirements.txt
```

结构越清晰，你以后越不想把它删掉。

### 2. 数据层（data）

核心职责：

* 从 API / CSV / Parquet 把 `日频 panel 数据` 抽象成统一格式
* 加上标的元数据（行业、国家、市值等）

典型数据形式：

```python
# 方式一：长表
# index: (date, asset) MultiIndex
# columns: ['open','high','low','close','volume', ...]
prices: pd.DataFrame

# 方式二：dict of DataFrame
prices['close']  # index: date, columns: asset
prices['volume']
```

要准备的东西：

* `load_prices()`：从本地 / API 拉一个时间段的数据
* `load_universe()`：返回当前可交易标的集合
* `load_metadata()`：行业、风格分类、是否 ST / 停牌等等

### 3. 因子层（factors）

职责：

* 对每个日期、每个资产算出一堆因子值
* 标准输出格式：`DataFrame(index=(date, asset), columns=factor_name)`

比如：

```python
def momentum(prices, lookback=126) -> pd.DataFrame:
    ...

def value(pe, pb) -> pd.DataFrame:
    ...

def quality(roa, roe, leverage, ...) -> pd.DataFrame:
    ...
```

这里要注意：

* 缺失值处理（新上市 / delist / 停牌）
* 滞后处理（避免 look-ahead bias：例如因子用 t−1 的信息）
* 标准化与行业中性化（后面 v2 会用）

### 4. 回测 & 组合层（backtest + portfolio）

拆成两个部分会更干净：

**Portfolio 层：**
输入：

* 某一时刻的因子值 / ML 预测值
* 约束（最大权重、行业限额、现金比例等）

输出：

* 一组目标权重 `w_t (asset)`

可以有几种实现方式：

* 简单打分 + 排名（top N / long-short）
* 均权 / 风险平价
* 二次规划（最小方差 / mean-variance with constraints）

**Backtest 层：**
负责「把权重变成时间序列的 P&L」。

主要组件：

* `Account`：记录现金、持仓、当前市值
* `Broker`：根据权重生成订单、应用交易成本 / 滑点
* `BacktestEngine`：驱动日期循环，更新价格 → 调整权重 → 更新账户 → 记录结果

输出：

* `equity_curve: pd.Series(index=date)`
* `trades: pd.DataFrame`（每笔交易）
* `positions: pd.DataFrame(index=date, columns=asset)`

### 5. 指标 & 评估层（metrics）

这层就是把回测结果「做体检」：

* 收益相关：

  * 总收益、年化收益
  * 波动率（年化）
  * Sharpe、Sortino
  * 最大回撤 / Calmar
  * 换手率、胜率、平均盈亏

* 统计检验：

  * t-stat of mean return
  * Deflated Sharpe（防止多策略 data mining）

最好设计一个统一接口：

```python
def evaluate_equity(equity: pd.Series, freq: str = "D") -> dict:
    ...

def evaluate_trades(trades: pd.DataFrame) -> dict:
    ...
```

### 6. ML 扩展层（ml）

目标：横截面预测，如预测「下一个月的超额收益」。

管线建议：

* `FeatureBuilder`：

  * 用因子 + technical features + metadata 拼出特征矩阵
  * 输出 `(X, y, meta)`，带有 `date`、`asset` 做索引

* `DataSplit`：

  * 按时间切 `train / valid / test`
  * 支持 walk-forward / expanding window

* `ModelWrapper`：

  * 封装 sklearn / xgboost / lightgbm / pytorch 等
  * 提供 `fit() / predict() / save() / load()`

* `Evaluator`：

  * 把预测值转回权重 → 喂给 backtest engine
  * 做真正的样本外回测，而不是只看 MSE / R²

重点：

* 每一个步骤都要「按时间」切，防止数据泄露
* 特征构造、标准化只用训练集的统计量

### 7. 执行仿真层（exec_sim）

Almgren–Chriss 类型模型可以单独放：

* 输入：

  * 初始持仓 / 订单大小
  * 预期波动、流动性参数、风险厌恶系数
* 输出：

  * 拆分到多时间点的执行计划
  * 每一段执行的预期成本 / 风险

你可以做成一个 `ExecSimulator`：

```python
class ExecSimulator:
    def __init__(self, sigma, gamma, eta, ...):
        ...

    def optimal_schedule(self, Q, T, N):
        """总量 Q，在总时间 T 内、N 段执行的最优路径"""
        ...

    def simulate(self, schedule, random_seed=None):
        """模拟真实价格路径下的实现成本"""
        ...
```

## 二、构建过程：怎么从 0 跑到 v2.5

人类总是喜欢一次性想完所有功能，然后卡死在第一步。你就按版本来拆任务。

### Step 0：环境 & 基础搭好

* 仓库初始化（git + GitHub）
* 选 Python 为主（pandas / numpy / matplotlib 起步）
* 写 `requirements.txt`，随便用 venv 或 conda，不要裸跑

### Step 1：实现 v0（数据 + 基础因子 + 简单回测）

目标：能跑出第一条 equity curve，不好也行，先活着。

1. **数据：**

   * 先用现成 CSV（比如公开的 SPY / QQQ / AAPL 等历史数据）
   * 实现 `load_prices()`，仅支持「某个指数成分的若干股票」

2. **因子：**

   * 动量：`close[t] / close[t-lookback] - 1`
   * 简易价值：用市净率 / PE（如果没 fundamental，就先跳过）
   * 质量：没有财报先空着，之后补

3. **回测：**

   * 每月调仓一次：

     * 按动量因子排序，选 top 20% 做多，bottom 20% 做空，等权
   * 没有手续费、没有滑点
   * 输出 equity curve + 简单指标（累计收益、年化、波动、Sharpe）

这个阶段不要碰 QP、不要碰 ML，用最原始的规则验证「端到端 pipeline 能跑」。

### Step 2：v1（严肃一点的回测 +指标）

基于 v0 的 pipeline，升级：

1. **时间切分：**

   * 比如 2005–2015 训练 / 调试，2016–2022 做样本外
   * 配一个简单的 `Config`：指定 backtest 时间范围、再平衡频率等

2. **成本模型：**

   * 固定双边手续费（如 5 bps）
   * 滑点可以设为成交量的函数 / 固定 bps 都行，先用简单版本

3. **指标：**

   * 实现年化收益、波动、Sharpe、max DD、换手率
   * 输出成一个 dict + 终端表格 / notebook 图

到这里，你已经有一个「像回事的回测系统」。

### Step 3：v2（多因子 + 组合优化 + Walk-forward）

现在才把你喜欢的「量化研究」加进去：

1. **多因子合成：**

   * 对每个因子做：去极值 → 标准化 → 行业中性化
   * 用线性组合 / 主成分 / 回归残差构出综合 score

2. **组合优化（QP）：**

   * 用 cvxpy 或类似库实现：

     * 目标：最大化 `μᵀw - λ wᵀΣw` 或最小化方差
     * 约束：`sum w = 1`、`|w_i| <= w_max`、行业权重上限等

3. **Walk-forward：**

   * 时间轴按窗口滚动：

     * 用 [t0, t1] 拟合因子权重 / 协方差
     * 在 (t1, t2] 回测
   * 组合所有区间得到整段 equity curve

4. **更严谨的评估：**

   * 计算 Deflated Sharpe 或至少对「多策略测试」做简单修正
   * 显示不同阶段的表现（rolling Sharpe / rolling drawdown）

到这步，你已经有「数据 → 因子 → 优化 → 回测 → 严肃评估」一整条链，基本可以在简历上写成一个完整 quant research 项目了。

### Step 4：v2.5（ML 横截面 + 真正的样本外）

这一步把你对 ML 的兴趣接上来，但核心依旧是「样本外回测」。

1. **特征构造：**

   * 用你已有的因子 + 技术指标（波动率、成交量变化等）
   * 构成 `(date, asset)` 对应一行的 `X`，target 是下一期收益 `y`

2. **数据切分：**

   * 时间滚动切分：train → valid → test
   * 注意：标准化 / PCA 必须只用 train 的统计量，应用到 valid/test

3. **模型：**

   * 先用树模型（RandomForest / GBDT）
   * 输出的是「预测超额收益」，再按 rank 构建组合

4. **评估：**

   * 不要只看 MSE / R²，必须把预测输出喂给回测引擎
   * 和纯因子策略对比：收益 / 风险 / 回撤 / turnover
   * 做一个简单的「feature importance / 因子暴露」可视化

### Step 5：exec-sim（执行仿真）

单独做个小模块，但和 Alpha-Lab 共用数据结构：

* 从回测生成的目标权重 / 目标换手量中抽取「大单」
* 用 Almgren–Chriss 模型给出不同风险偏好的最优执行路径
* 做几个情景：

  * 不同波动 / 流动性
  * 不同风险厌恶参数
* 输出：

  * 实际执行成本分布
  * 成本 vs 风险的 trade-off 图

这块是简历里很「加分」的独特点。

### 1.2 `config/paths.py`：路径配置

#### 职责

* 唯一可信的「路径真相中心」
* 管理项目根目录、数据目录、输出目录、日志目录、图表目录
* 提供构造具体文件路径的工具函数（例如：某个回测 run 的输出目录）

#### 需要定义的核心内容

1. **常量 / 全局变量**

   * `PROJECT_ROOT`: 项目根目录

   * `FIG_DIR`: 图表输出目录

2. **路径构造函数（接口级，自己实现）**

   示例签名：

   ```python
   from pathlib import Path

   def project_root() -> Path:
       ...

   def data_dir() -> Path:
       ...

   def output_dir() -> Path:
       ...

   def log_dir() -> Path:
       ...

   def fig_dir() -> Path:
       ...

   # 针对原始数据文件
   def raw_data_path(filename: str) -> Path:
       ...

   # 针对回测结果（按 run_name 分目录）

       ...
   ```

3. **初始化 / 确保目录存在**

   ```python
   def ensure_directories() -> None:
       """
       创建 DATA_DIR / OUTPUT_DIR / LOG_DIR / FIG_DIR 等不存在的目录。
       """
       ...
   ```

#### 实现 Checklist

* [ ] 使用 `pathlib.Path` 而不是拼字符串
* [ ] 所有目录路径通过函数暴露（不要到处 import 某个硬编码常量）
* [ ] 加一个简单的 docstring 说明每个函数返回什么
* [ ] 不在这里 import 任何上层模块，避免循环依赖

### 1.3 `config/backtest.py`：回测参数配置

#### 职责

* 把「这次回测怎么玩」写进一个结构化配置：起止时间、调仓频率、交易成本、初始资金、基准指数、用哪个价格字段等。

#### 需要定义的核心内容

1. **频率 / 常量**

   例如（自己决定形式，可以枚举也可以字符串常量）：

   * 回测频率：`"D"`, `"W"`, `"M"`
   * 调仓依据价格字段：`"open"`, `"close"` 等

2. **回测配置数据结构**

   建议用 `dataclass` 定义一个 `BacktestConfig`：

   ```python
   from dataclasses import dataclass

   # DateLike 可以以后在 utils.typing 里定义
   # 这里可以先用 str / pd.Timestamp，占个位
   @dataclass
   class BacktestConfig:
       start_date: "DateLike"
       end_date: "DateLike"
       rebalance_freq: str          # 'D', 'W', 'M'
       initial_cash: float
       commission_bps: float        # 手续费，基点
       slippage_bps: float          # 滑点，基点
       price_field: str             # 'open' 或 'close'
       benchmark: str | None = None # 基准指数/ETF 代码，可选
   ```

3. **默认配置工厂函数**

   ```python
   def default_backtest_config() -> BacktestConfig:
       """
       返回一套默认回测配置。
       """
       ...
   ```

   使用场景：

   * notebook / demo 里：`cfg = default_backtest_config()` 然后局部修改字段
   * 单元测试里快速构造 config

#### 实现 Checklist

* [ ] 定好 `BacktestConfig` 的必需字段和默认值
* [ ] 保证 start_date / end_date 的类型统一（字符串还是 Timestamp，自己选一个）
* [ ] 写一个默认配置函数，给出合理的示例参数
* [ ] 不在这里 import `pandas` 的 heavy 东西（可以先用 `str` 表示日期）
